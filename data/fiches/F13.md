# Serveur, base de données ou API en erreur

## Symptômes
Erreurs 500, 502 ou 503, timeouts, CPU ou mémoire saturés, base de données inaccessible, pods Kubernetes en redémarrage.
## Diagnostic
1. Consulter la supervision : alertes actives, métriques CPU, mémoire, disque.
2. Vérifier les derniers déploiements (retour arrière possible ?).
3. Vérifier la base de données : connexions actives, verrous.
## Actions
- Après un déploiement : retour à la version précédente.
- Saturation : ajouter des instances ou redémarrer selon le runbook.
## Escalade
Astreinte Infrastructure, puis cellule incident si impact voyageurs.
